# Q2: Builder Phase (Weeks 13–25)

> **Dates:** March 2 → May 31, 2026  
> **Theme:** Stop practicing, start building the real game  
> **Entry Requirement:** Q1 vertical slice complete, concept locked

---

## Q2 Objectives

1. **Game Design Document (GDD) v1** — Lock scope, features, content targets
2. **Asset Pipeline at Scale** — Create assets faster, establish templates
3. **Core Systems Complete** — All major mechanics implemented (not polished)
4. **Content Backlog Started** — Real towers/cards/enemies, not prototypes
5. **First External Playtest** — Someone outside your head plays your game

---

## Weekly Rhythm Shift

| Q1 Rhythm | Q2 Rhythm |
|-----------|-----------|
| Learn something new each week | Apply what you know to the game |
| Weekly POC (any mechanic) | Weekly feature/content milestone |
| Study games broadly | Study your game (playtest, iterate) |
| Art practice exercises | Art production for the game |

**Schedule stays the same** (Mon=Art, Tue=Blender, etc.) but activities serve the game, not skill-building.

---

## Q2 Milestone Map

### Weeks 13–14: GDD & Scope Lock
**Goal:** Write it down so you can't lie to yourself

- Create `gdd.md` with:
  - One-liner (from Q1)
  - Core loop diagram
  - Complete feature list (must-have / nice-to-have / cut)
  - Content targets: X towers, Y enemies, Z levels/rounds
  - Progression system outline
  - Monetization thoughts (if any)
- Scope gut-check: Can you build this in 6 months?
- Cut 30% of what you think you need

**POC:** GDD v1 document + revised vertical slice reflecting scope

---

### Weeks 15–17: Core Systems Build
**Goal:** All mechanics functional (ugly is fine)

Depending on your game direction:

**If Tower Defense:**
- Tower placement / selling / upgrading
- Enemy waves system (spawning, pathing, escalation)
- Economy (gold earn, spend, balance)
- Win/lose conditions
- Level/map system (even if one map)

**If Card Game:**
- Full deck system (draw, discard, shuffle, exhaust)
- Hand management
- Card effect system (modular, data-driven)
- Resource/mana system
- Turn structure
- Win/lose conditions

**If Hybrid:**
- Define which systems from each
- Build the integration layer

**POC:** Feature-complete prototype (all systems work, nothing polished)

---

### Weeks 18–20: Content Pipeline
**Goal:** Make assets fast and consistent

- Create template files:
  - Blender scene with lighting/camera preset
  - Procreate canvas with color palette
  - Godot scene templates (tower, enemy, card, etc.)
- Batch workflow: Concept → Model → Render → Import
- Target: 2–3 complete assets per week at quality bar
- Start building real content backlog:
  - 5 towers/cards minimum
  - 5 enemies minimum
  - UI complete

**POC:** 5+ real game assets (not prototypes), all in-game

---

### Weeks 21–23: Content Sprint
**Goal:** Fill out the game

- Continue asset production
- Level/round design (10+ waves or equivalent)
- Balance pass v1 (spreadsheet time)
- Audio for all new content
- Progression hooks (unlocks, rewards)

**POC:** 20+ minutes of playable content

---

### Weeks 24–25: External Playtest
**Goal:** Someone else plays your game

- Build a "playtest build" (stable, instructions included)
- Find 3–5 playtesters (friends, family, internet strangers)
- Create feedback form (simple: What was fun? What was confusing? Would you play more?)
- **Watch someone play without helping them**
- Document all feedback
- Prioritize fixes for Q3

**POC:** Playtest report with prioritized action items

---

## Q2 Agentic Automation Checkpoint

By end of Q2, you should be able to document and potentially automate:

- [ ] Blender render pipeline (scene setup, export settings)
- [ ] Asset naming and folder conventions
- [ ] Godot scene structure templates
- [ ] Basic balance spreadsheet → game data pipeline

Start building your agent toolkit here — small scripts, templates, documented workflows.

---

# Q3: Production Phase (Weeks 26–38)

> **Dates:** June 1 → August 30, 2026  
> **Theme:** Feature complete, polish, iterate on feedback  
> **Entry Requirement:** All systems built, external playtest done

---

## Q3 Objectives

1. **Feature Complete** — No new mechanics after Week 30
2. **Content Complete** — All planned content in-game by Week 35
3. **Polish Pass** — Juice, feel, visual consistency
4. **Balance Iteration** — Multiple playtest cycles
5. **Steam Prep Begins** — Page, assets, wishlists

---

## Q3 Milestone Map

### Weeks 26–28: Feedback Integration
**Goal:** Fix what playtesters hated

- Address top 5 playtest issues
- Rework confusing systems
- Cut features that aren't working
- Add features that were missing (sparingly)
- Second playtest round (same or new testers)

**Output:** Improved build, second playtest report

---

### Weeks 29–30: Feature Lock
**Goal:** Stop adding, start finishing

- **FEATURE LOCK: No new mechanics after Week 30**
- Document everything that's in the game
- Update GDD to reflect reality
- Cut anything that isn't done
- This is the hardest week emotionally — embrace it

**Output:** Feature-locked build, final scope documented

---

### Weeks 31–33: Content Complete
**Goal:** Everything in, nothing placeholder

- All towers/cards final
- All enemies final
- All levels/rounds final
- All UI final
- All audio final
- Progression system complete (unlocks, saves)

**Output:** Content-complete build

---

### Weeks 34–35: Polish Sprint
**Goal:** Make it feel professional

- VFX pass (particles, screen effects)
- Animation polish
- UI juice (transitions, feedback)
- Audio mix and mastering
- Performance optimization pass
- Bug bash

**Output:** Polished build

---

### Weeks 36–38: Steam Setup
**Goal:** Store presence exists

- **Week 36:** Create Steamworks account, app ID, store page draft
- **Week 37:** Capture screenshots (in-game, clean, well-composed)
- **Week 38:** Create trailer (60–90 seconds, gameplay focus)

Steam page elements:
- [ ] Short description (< 300 chars)
- [ ] Long description
- [ ] 5+ screenshots
- [ ] Header/capsule images
- [ ] Trailer
- [ ] Tags and categories
- [ ] System requirements
- [ ] Early Access? (probably not for this scope)

**Output:** Steam page live (coming soon), wishlist tracking

---

## Q3 Playtest Rhythm

| Frequency | Type | Who |
|-----------|------|-----|
| Weekly | Self-playtest | You, every Sunday |
| Bi-weekly | Trusted playtest | 2–3 consistent testers |
| End of Q3 | Wider playtest | 10+ testers, fresh eyes |

Feedback loops are how you find the fun. Budget time for them.

# Q4: Ship Phase (Weeks 39–52)

> **Dates:** September 1 → December 25, 2026  
> **Theme:** Launch the game, survive the launch  
> **Entry Requirement:** Feature complete, Steam page live

---

## Q4 Objectives

1. **Release Candidate** — Stable, shippable build by Week 45
2. **Marketing Push** — Wishlists, content, community
3. **Launch** — Steam release (target: Week 50, December 11)
4. **Post-Launch** — Patch, respond, breathe

---

## Q4 Milestone Map

### Weeks 39–41: Beta Polish
**Goal:** Get to "good enough" quality bar

- Final bug bash
- Edge case handling
- Save/load testing
- Difficulty tuning
- Tutorial/onboarding polish
- Accessibility pass (colorblind options, key rebinding)

**Output:** Beta build, playtest with "is this shippable?" lens

---

### Weeks 42–44: Release Candidate
**Goal:** This is the version you'd ship tomorrow

- RC1 build
- Full playthrough (start to finish, no crashes)
- Platform compliance check
- Achievements (if any)
- Trading cards (if any, probably skip for v1)
- Final trailer (if initial one was rough)

**Output:** Release candidate build, all Steam deliverables ready

---

### Weeks 45–47: Pre-Launch Marketing
**Goal:** Get wishlists, build anticipation

- **Week 45:** Announce release date (4–6 weeks out)
- **Week 46:** Push wishlists (Reddit, Twitter/X, relevant communities)
- **Week 47:** Send keys to small creators/reviewers

Marketing activities (ongoing):
- Dev log posts (X, website, Steam community)
- GIF creation (short, punchy gameplay moments)
- Community engagement (respond to comments, be human)
- Press kit page (if time allows)

**Output:** 1,000+ wishlists (aspirational but track it)

---

### Weeks 48–49: Launch Prep
**Goal:** Survive launch day

- Confirm launch date in Steamworks
- Prepare launch day announcement
- Set up community hub (discussions, announcements)
- Test purchase flow (if possible, "coming soon" → buy)
- Clear your calendar for launch week
- Sleep bank. You'll need it.

**Output:** All systems go, launch date locked

---

### Week 50: LAUNCH (Target: December 11, 2026)

**Launch day:**
- Press "Release" in Steamworks
- Post announcements everywhere
- Monitor for critical bugs
- Respond to reviews (thank positives, acknowledge negatives gracefully)
- Don't doom-scroll metrics

**Launch week:**
- Hotfix critical issues if needed
- Engage with players
- Track: Sales, wishlists converted, reviews, refund rate

---

### Weeks 51–52: Post-Launch
**Goal:** Stabilize and recover

- Patch any major issues
- Read feedback, don't just react
- Start a "future updates" list
- Write a post-mortem for yourself
- Take time off. You shipped a game.

# Risk Register

Things that might blow up your timeline:

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Baby sleep regression | High | Medium | Protect evening focus time, accept slower weeks |
| Scope creep | High | High | Feature lock at Week 30, cut ruthlessly |
| Burnout | Medium | Critical | 15 min counts, rest weeks are allowed |
| Art taking too long | Medium | Medium | Simplify aesthetic, use more 3D→2D |
| Core loop isn't fun | Low | Critical | Catch in Q2 playtests, pivot early if needed |
| Steam page not ready | Medium | Medium | Start in Week 36, not later |
| Launch week chaos | High | Low | Plan for nothing else that week |

---

# Emergency Scope Options

If you're behind, cut in this order:

1. **Content:** Ship with 10 towers instead of 20
2. **Polish:** Good enough > perfect
3. **Features:** Cut progression system, ship core game
4. **Launch date:** Push to January 2027 (last resort, avoid if possible)

**Never cut:**
- Core loop quality
- Game stability
- Your health or family

---

# The One Rule

**Ship something on December 25, 2026.**

It doesn't have to be perfect. It doesn't have to be complete. It has to exist in the world as a playable game that someone can buy.

Everything else is negotiable.
